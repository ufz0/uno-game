# ATLAS.md — UNO card table

Real-time multiplayer UNO. Express + Socket.IO backend, vanilla JS client (no framework). 2–4 humans per table, optional bots, chat, room codes.

- `npm install`

- `npm test` — `node:test` suite. Engine unit tests (`test/engine.test.js`) + socket.io-client integration that plays full games to a winner (`test/flow.test.js`) + a room-cap test (`test/cap.test.js`) + headless 3D sim/physics tests (`test/3d.test.js`). All 31 pass.

- Docker: `docker compose up --build` — `Dockerfile` (node:22-alpine, non-root, healthcheck) + `docker-compose.yml` (port 3000). `.dockerignore` excludes node_modules/test.

## Layout
- `server.js` — Express static + Socket.IO rooms. One `rooms` Map keyed by 6-char code. Exports `{ app, server, io, rooms }` for tests.
- `lib/game.js` — pure rules engine (`Game` class), no I/O.
- `lib/cards.js` — deck build (108 cards), shuffle, `isWild`.
- `lib/bot.js` — `botMove(game, idx)` greedy card picker; mutates the game directly (server is single-threaded).
- `public/` — `index.html` (menu → lobby → table screens), `style.css` (3D HUD overlay styles), `app.js` (ES module: socket client + HUD), `table3d.js` (the 3D table: `CardSim` physics sim + `buildScene` + `createTable3D`).
- `public/vendor/` — browser builds of `three.module.min.js` + `cannon-es.js`, wired up via an importmap in `index.html` (no build step). **Keep these in sync with the npm versions in `package.json`** — the npm copies exist so CI can run the headless physics tests.
- `test/` — node:test suites.

## Key conventions / gotchas (learned the hard way)
- **Socket ack order is `(payload, cb)` everywhere.** The client `emit()` helper and the test `emitAck()` always send a payload first. Server handlers that take no payload use `(_payload, cb)`. Do NOT write `(cb)` — the payload lands in `cb` and `cb?.()` throws.
- **`isPlayable(card, hand)`** needs the hand: wild4 is only legal if the player holds no card of the current color. `playableCards(hand)` threads the hand through.
- **`playCard` applies the card effect first, then handles UNO/win.** A skipped/penalized last card still resolves its effect. Don't reorder.
- **Reverse:** flips direction, then `advance(players.length === 2 ? 2 : 1)`. Two players → acts as a skip (turn returns to the player). 3+ → moves to the next seat against the new direction.
- **Turn/UNO:** `unoCalled` must be true to win on an empty hand; otherwise the player draws 2 (penalty). Bots auto-call UNO when they hit 1 card.
- **Test state races:** attach a persistent `socket.on('state')` tracker *before* the first broadcast, or the initial state is missed and `awaitState` times out. The server broadcasts state before resolving the ack, so a cached `_st` is fresh after `emitAck` resolves.
- **Lobby is for party tables only.** `create` with bots > 0 deals straight away (creator is marked ready, `startGame` runs inside the create handler — no ready-up, no lobby). Party tables (the "Party" chip, 0 bots) wait in the lobby: every human must emit `ready {on:true}` before the host's `start` is accepted; bots count as ready. `stateFor` carries `allReady` + per-player `ready` for the UI.
- **`#over` starts `hidden` in the HTML.** `renderOver` must set `over.hidden = false` on a normal game end (the `kicked` handler does it for the kicked screen). This was the "game won but the table just sits still" bug — the win screen was never unhidden, in any player count or outcome.
- **Security posture (2026-09 audit):** one room per socket — `create` auto-leaves the current room first, `join` refuses if already seated (otherwise a socket sat in many rooms and only the first was cleaned up on disconnect → leak/DoS). `MAX_ROOMS` (env, default 100) caps tables; a seated socket may still move to a fresh table at the cap. Room codes are 6 chars from a 32-char set (~1.07B) so probing for live lobbies via `join` is impractical. `broadcast` skips stale socket ids and a socket-level `error` listener disconnects — an uncaught exception anywhere kills the whole process and every table. HTTP responses carry a CSP (`script-src 'self'`, which also contains the Google Fonts dependency), `X-Frame-Options: DENY`, `nosniff`, and `X-Powered-By` is off. Client XSS surface is handled: every user-controlled string (names, chat) goes through `esc()` before `innerHTML`, the rest use `textContent`.
- **Rematch flow (server-driven):** on `status === 'over'` the room gets a `room.rematch` with a per-human 30s timeout (`REMATCH_MS`, env-overridable — tests set it to 4000). `rematch {again:true}` records a vote and clears that player's timer; `{again:false}` routes to `leave()`. When every remaining human has voted, `maybeStartNext` locks (clears all timers — this is the "skip the rest"), broadcasts, emits `reshuffle {count}` to each human, and starts the next round after `RESHUFFLE_MS` (1800, the client's animation window). Timed-out humans are kicked via `kickPlayer(room, sid, 'timeout')`.
- **`kickPlayer` is the single removal path** for kicked/timeout players: removes from `room.humans`, emits `kicked {reason:'host'|'timeout'}` to the victim, drops the seat (or bot-takes-over mid-game), transfers host if needed, and re-evaluates the rematch. Any new removal path should go through it.
- **Room teardown goes through `destroyRoom`** (clears rematch timers + start timer + turn/bot timers, deletes from `rooms`). A room is destroyed whenever `room.humans.size === 0` — even mid-game (previously a all-bots room would leak and play forever).
- **Ghost seats:** `startNextRound` drops human seats whose socket is no longer in `room.humans` before dealing; if that leaves <2 players the table falls back to the lobby instead of starting.
- **Client reshuffle animation** is WAAPI (`el.animate`) on card backs spawned in `#shuffle-layer`; triggered by the `reshuffle` socket event, cleaned up when the next `playing` state lands. Don't gate it on state alone — the `locked` state and the event arrive together, and the event is the one-shot trigger.
- **3D table (`table3d.js`)** — the felt was replaced by a real 3D scene (dark room, walnut table, 4 seats with simulated hands, hanging lamp). `CardSim` is pure physics/logic (no DOM/WebGL, node-testable); `buildScene()` builds the three.js scene graph; `createTable3D(container, {onCardClick, onDeckClick, labels})` owns the renderer, the fixed-1/60 accumulator loop, raycast interaction and camera lean, and returns `{sim, sync, reshuffle, setOver, reset, dispose}`. `app.js` (now an ES module) calls `sim.sync(st, prev)` per state — play detection (top.id changed, actor = `prev.turn`), hand diffing by card id (new → draw, gone → recall), opponent count self-heal, `setDeckCount`/`setTop` all live there, so the 2D `prevState` gotcha no longer exists.
- **3D card lifecycle — bodies only for `flying`/`table` cards.** Card states: `held`/`anim`/`deck` = pure visuals (transform on `c.pos`/`c.quat`, no physics body), `flying` = DYNAMIC body, `table` = KINEMATIC body (frozen pile). `_spawnBody`/`_despawnBody` manage it. **Why:** a fanned hand is a stack of overlapping boxes — a body in the hand gets crushed by the solver the moment a neighbour is released (toss velocity killed, card stuck). Only cards in the world collide. The canonical transform is always `c.pos`/`c.quat` (the sim writes it from the body for flying/table); the render loop reads that, never the body.
- **cannon-es gotchas (all hit in the wild):** (1) no static `CANNON.Quaternion.slerp(a,b,t)` — it's the instance method `a.slerp(b, t)`; (2) no `Vec3.add` — it's `vadd`; (3) KINEMATIC bodies still integrate `pos += velocity*dt` in `world.step` — zero velocity when you freeze a card, or it drifts forever; (4) the friction solver re-injects a limit-cycle of angular velocity (~1.4 rad/s) on ANY card in resting contact — a flat card "spins" forever and the rest timer never fires; `_killRestSpin()` zeroes `angularVelocity` after every substep for cards with speed < 0.15 (a tossed card never dips below ~1.2 m/s before landing, so low speed = at rest); (5) GSSolver friction kills tangential velocity almost instantly (1.5 m/s → 0 in ~0.2 s) regardless of the friction value — the toss must carry the card most of the way to the discard in the air; (6) the physics box is 9 mm thick (`PHYS_T`) while the visual card is 3 mm, and the world steps 2× per sim tick (`dt/2` twice) so a fast toss can't tunnel through the table top.
- **3D top-card matching by id OR face id.** An opponent's played card keeps its old hand id; only its `face` becomes the new top (`reveal`). `sim.topCard()` matches `c.id === topId || c.face.id === topId` — used by `setTop`, the freeze-tidy and the gold top ring. Matching by id alone left face-down cards untidied (the "opponent played a red 5, top ring shows a card back" bug).
- **Headless tests:** texture functions return `null` when `document` is undefined (placeholder materials), so `CardSim` + `buildScene` import in bare node — `test/3d.test.js` (10 tests) drives the real physics: deal orientations, toss→land→freeze, opponent flip, draw, recall, deck reconcile, reshuffle, pile stability, scene graph.

## Design identity (keep it consistent)
3D table: dark room (near-black walls), square walnut table, warm hanging lamp (the only light), 4 chairs with simulated hands. UNO palette (red #e5311b, yellow #f2a900, green #009a4d, blue #0669b0), paper #f5f2e8, ink #10131a. Display: Archivo italic 800/900. Body: Instrument Sans. Cards = colored field + tilted oval tinted 50% card color / ink + white face (canvas textures in `table3d.js`) — the tint is what makes hand cards identifiable by color. The DOM HUD (seat labels, turn timer, chips, plate) overlays the 3D view; keep it out of the WebGL scene. See `:root` tokens in `style.css`.
