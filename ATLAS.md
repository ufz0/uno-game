# ATLAS.md — UNO card table

Real-time multiplayer UNO. Express + Socket.IO backend, vanilla JS client (no framework). 2–4 humans per table, optional bots, chat, room codes, auto-rejoin after a dropped connection.

## Git rule (user instruction — this project only)
- **Commit only to `dev`. Never commit to `main`.** All feature work happens on `dev`; `main` is updated only via PRs. This rule was given for this repo and applies to no other project.
- Repo: https://github.com/ufz0/uno-game (public). Push `dev` after changes; `dev` is the live branch. `main` tracks `dev` via PRs (#1–#3 merged); `dev` is normally only ahead by pending doc commits until the next merge.

## Run / test
- `npm install`
- `npm start` (or `npm run dev` for watch) — serves `public/` + Socket.IO. `PORT` env overrides (default 3000).
- `npm test` — `node:test` suite, 8 files, **81 tests, all pass**: `cards` (deck composition/shuffle/isWild), `bot` (the greedy brain), `engine` (full rules engine incl. callUno/canStart/reverse/draw2/exhausted-deck), `flow` (socket.io room lifecycle: create/join/rejoin/ready/kick/start, add/remove-bot, voluntary leave, mid-game disconnect, host transfer, UNO, toasts, name sanitisation, full table, chat throttle, rematch vote + timeout + opt-out), `http` (health, static serving, security headers, 404s), `turn` (the turn-timer auto-pass), `cap` (room cap), `persist` (restart simulation: mid-game survival incl. chat, expired turn auto-pass on restore, rematch timeouts → next round / room teardown, and rejoin after a restart for seat + host + rematch vote). The suite takes ~1–2 minutes — `flow`/`turn` play real games on real timers; don't mistake that for a hang. **Every test file runs in its own process**, and since the server is imported into that same process, *close every client socket at the end of a test* or `server.close()` in `after()` never resolves and the run hangs.
- Timers are env-overridable for tests: `REMATCH_MS`, `MAX_ROOMS`, `TURN_MS`, `CHAT_MIN_MS` (all `Number(process.env.X) || default`), and `DATA_FILE` (persistence path). `turn.test.js` sets `TURN_MS=800` to observe the auto-pass; `cap.test.js` sets `MAX_ROOMS=3`; `flow.test.js` sets `CHAT_MIN_MS=1000` for the throttle test. **Every test file that imports the server must import `test/_env.js` first** — it points `DATA_FILE` at a per-process tmp file so leftover state from a real server run can't leak into the rooms map (this bit the `cap` test: pre-loaded rooms count against the cap).
- Lint/format: `npm run lint` (ESLint flat config, `eslint.config.js` — @eslint/js recommended + node/browser globals union, `io` declared for `public/` since Socket.IO's client script injects it), `npm run lint:fix`, `npm run format` / `npm run format:check` (Prettier, `.prettierrc.json`: singleQuote + printWidth 100; `*.md` ignored — prose keeps its own flow). Prettier quirk to know: it preserves a string's original quotes when the string contains the other quote type (hence the mixed-quote CSP array — that's stable, not drift).
- CI: `.github/workflows/ci.yml` — three parallel jobs on pushes to `dev`/`main` and PRs targeting `main`, with `cancel-in-progress`. `syntax` runs `node --check` over every JS file (server/lib/public/test) as a fast gate; `lint` runs `npm run lint` + `npm run format:check`; `test` runs `npm ci && npm test` across a **Node 20 / 22 / 24 matrix** (`fail-fast: false`). Node 22 matches the Docker image; Node 18 is past EOL and predates the `--test-force-exit` flag the test script uses, so it's intentionally not in the matrix. Verified green on Node 22 and 26 locally. A second workflow, `publish-image.yml`, builds the multi-arch image and pushes it to GHCR on every push/merge to `main` (auth via the `GHCR_TOKEN` repo secret) — see the "Image registry" note below.
- Health: `GET /api/health` → `{"ok":true}`.

## Layout
- `server.js` — Express static + Socket.IO rooms. One `rooms` Map keyed by 6-char code. Exports `{ app, server, io, rooms }` for tests.
- `lib/game.js` — pure rules engine (`Game` class), no I/O.
- `lib/cards.js` — deck build (108 cards), shuffle, `isWild`.
- `lib/bot.js` — `botMove(game, idx)` greedy card picker; mutates the game directly (server is single-threaded).
- `lib/persist.js` — room (de)serialization (Set/Map ↔ JSON) + load/save with a missing-or-corrupt file tolerated. Pure I/O helpers; the debounce, rehydration, and restore semantics live in `server.js`.
- `public/` — `index.html` (menu → lobby → table screens), `style.css` (felt-table aesthetic), `app.js` (socket client + renderers).
- `scripts/push-image.sh` — build + push the Docker image to GHCR (see "Image registry" above).
- `test/` — node:test suites.

## Key conventions / gotchas (learned the hard way)
- **Socket ack order is `(payload, cb)` everywhere.** The client `emit()` helper and the test `emitAck()` always send a payload first. Server handlers that take no payload use `(_payload, cb)`. Do NOT write `(cb)` — the payload lands in `cb` and `cb?.()` throws.
- **`isPlayable(card, hand)`** needs the hand: wild4 is only legal if the player holds no card of the current color. `playableCards(hand)` threads the hand through.
- **`playCard` applies the card effect first, then handles UNO/win.** A skipped/penalized last card still resolves its effect. Don't reorder.
- **Reverse:** flips direction, then `advance(players.length === 2 ? 2 : 1)`. Two players → acts as a skip (turn returns to the player). 3+ → moves to the next seat against the new direction.
- **Turn/UNO:** `unoCalled` must be true to win on an empty hand; otherwise the player draws 2 (penalty). Bots auto-call UNO when they hit 1 card.
- **Test state races:** attach a persistent `socket.on('state')` tracker *before* the first broadcast, or the initial state is missed and `awaitState` times out. The server broadcasts state before resolving the ack, so a cached `_st` is fresh after `emitAck` resolves.
- **Lobby is for party tables only.** `create` with bots > 0 deals straight away (creator is marked ready, `startGame` runs inside the create handler — no ready-up, no lobby). Party tables (the "Party" chip, 0 bots) wait in the lobby: every human must emit `ready {on:true}` before the host's `start` is accepted; bots count as ready. `stateFor` carries `allReady` + per-player `ready` for the UI.
- **`#over` starts `hidden` in the HTML.** `renderOver` must set `over.hidden = false` on a normal game end (the `kicked` handler does it for the kicked screen). This was the "game won but the table just sits still" bug — the win screen was never unhidden, in any player count or outcome.
- **Security posture (2026-09 audit):** one room per socket — `create` auto-leaves the current room first, `join` refuses if already seated (otherwise a socket sat in many rooms and only the first was cleaned up on disconnect → leak/DoS). `MAX_ROOMS` (env, default 100) caps tables; a seated socket may still move to a fresh table at the cap. Room codes are 6 chars from a 32-char set (~1.07B) so probing for live lobbies via `join` is impractical. `broadcast` skips stale socket ids and a socket-level `error` listener disconnects — an uncaught exception anywhere kills the whole process and every table. HTTP responses carry a CSP (every source locked to `'self'`; the only exceptions are `fonts.googleapis.com`/`fonts.gstatic.com` for Google Fonts, plus `object-src 'none'` and `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`, and `X-Powered-By` is off. Client XSS surface is handled: every user-controlled string (names, chat) goes through `esc()` before `innerHTML`, the rest use `textContent`.
- **Rematch flow (server-driven):** on `status === 'over'` the room gets a `room.rematch` with a per-human 30s timeout (`REMATCH_MS`, env-overridable — tests set it to 4000). `rematch {again:true}` records a vote and clears that player's timer; `{again:false}` routes to `leave()`. When every remaining human has voted, `maybeStartNext` locks (clears all timers — this is the "skip the rest"), broadcasts, emits `reshuffle {count}` to each human, and starts the next round after `RESHUFFLE_MS` (1800, the client's animation window). Timed-out humans are kicked via `kickPlayer(room, sid, 'timeout')`.
- **`kickPlayer` is the single removal path** for kicked/timeout players: removes from `room.humans`, emits `kicked {reason:'host'|'timeout'}` to the victim, drops the seat (or bot-takes-over mid-game), transfers host if needed, and re-evaluates the rematch. Any new removal path should go through it.
- **Room teardown goes through `destroyRoom`** (clears rematch timers + start timer + turn/bot timers, deletes from `rooms`). A room is destroyed whenever `room.humans.size === 0` — even mid-game (previously a all-bots room would leak and play forever).
- **Ghost seats:** `startNextRound` drops human seats whose socket is no longer in `room.humans` before dealing; if that leaves <2 players the table falls back to the lobby instead of starting.
- **Client reshuffle animation** is WAAPI (`el.animate`) on card backs spawned in `#shuffle-layer`; triggered by the `reshuffle` socket event, cleaned up when the next `playing` state lands. Don't gate it on state alone — the `locked` state and the event arrive together, and the event is the one-shot trigger.
- **Rejoin after a dropped connection (2026-09):** socket.io reconnects as a *new socket id*, so the server keeps a rejoin path: mid-game a disconnect marks the seat `disconnected` (the game keeps running); `rejoin {code, name}` (server, after `join`) re-attaches a fresh socket to that seat — it re-uses the existing player (swaps `p.id` to the new socket id, clears `disconnected`) rather than adding a new one, and works while `status === 'playing'` **or `'over'`** (the rematch screen — the seat is still valid there; the seat's vote/deadline/timer get re-keyed from the old id to the new one, or the UI and the timeout would act on a ghost). Lobby drops delete the seat, so lobby returns just `join` again. **Rejoin must also remove the old id from `room.humans`** (a ghost id would keep the room alive forever and block destruction) **and transfer `room.host` if it pointed at the old id** (otherwise the host loses their controls). Client (`app.js` `disconnect`/`connect` handlers): on `disconnect` it snapshots `{code, name, screen, status}` from `S.st` and shows a persistent toast; on `connect` it emits `rejoin` (table, `playing` or `over`) or `join` (lobby), and on a refused rejoin lands on the menu with the server's error. A player who *voluntarily* left mid-game became a bot (`(away)`), not `disconnected` — they cannot rejoin, by design.
- **Persistence (2026-09):** tables are mirrored to a JSON file — `DATA_FILE` env (default `data/rooms.json`; Docker: named volume `uno-data` on `/app/data`, dir pre-created + chowned in the Dockerfile so the non-root user can write). Writes are debounced 300ms (timer is `unref`'d so a pending save never holds the process open) and atomic (tmp file + rename); a flush happens on SIGINT/SIGTERM/`exit`. Persistence is **best-effort by design** — `flushPersist` swallows disk errors, a write failure must never take the table down. Save hooks: every state change funnels through `broadcast()` or `destroyRoom()`, so those two (plus the `chat` handler, the one path that bypasses broadcast) call `persistRooms()`. On boot, `reloadRooms()` loads the file and `rehydrateRoom()` rebuilds the live timers from persisted **deadlines** (turn deadline, per-human rematch deadlines, the locked `startAt`); deadlines that slipped past while down fire immediately (auto-pass / kick). `Timeout` objects are never serialized. **Restore semantics:** lobby → dead human seats are dropped (bots kept), the dead host pointer is cleared, and `join` hands the host to the next sitter (it checks `io.sockets.sockets.has(room.host)`); mid-game/`over` → human seats are marked `disconnected` so rejoin can hand them back, the persisted host id stays (rejoin transfers it when that human returns). Verified end-to-end with a real SIGTERM/restart cycle, not just the in-process tests.
- **Chat is throttled per socket** (`CHAT_MIN_MS`, default 400ms — the check sits in the `chat` handler before the blank check; `socket.data.lastChat` is the state). A spammy client must not be able to re-render (and freeze) the other three tabs.
- **`roomOf` is pointer-first:** the room is pinned on `socket.data.room` at create/join/rejoin and unpinned at leave/kick; the function falls back to the old room scan so a stale pointer can never strand a seated player. Any new path that seats a socket must pin, and any path that unseats one must unpin.
- **Exhausted deck:** with 107 cards in hands and one in the discard, a reshuffle cannot refill the draw pile — `drawCards` then returns *fewer* cards (never `undefined`; pushing one used to crash the process inside `stateFor`/`botMove` via `isPlayable`). `draw()` only pushes when it got a card, but still sets `drewThisTurn` so the player can pass. Regression test in `engine.test.js`.
- **Duplicate names get a numbered suffix** (`uniqueName`, applied in `join`): chat "you" attribution and the lobby list are both name-keyed, so two "Lukas"es would be ambiguous.
- **Opponent hands are client-rendered fans of card backs** (`renderOpps` in `app.js`): each opponent gets an area on the felt (top for 1, top corners for 2, left/top/right for 3) with a name label, live count, and a gold turn glow. A play is detected as "`st.top` changed and the previous state's `turn` was this opponent" — their middle back flies to the discard; count gains get the `just-in` pop. The fan DOM *is* the state (count = child element count, self-healing after missed states) and `#opps` is rebuilt on a fresh deal. Gotchas: `dataset` values are strings — key opponent elements by `String(p.index)`, or a duplicate element spawns on every state. And `S.prevState` must be assigned at the *top* of `onState` (before any renderer runs) — if it lags one state behind, the flight animates on the wrong turn (or never), which looks like "animations only play on my own plays".

## Design identity (keep it consistent)
Felt-green table, wooden rail, UNO palette (red #e5311b, yellow #f2a900, green #009a4d, blue #0669b0), paper #f5f2e8, ink #10131a. Display: Archivo italic 800/900. Body: Instrument Sans. Cards = colored field + tilted oval tinted 50% card color / ink (`color-mix`) + white face — the tint is what makes hand cards identifiable by color. See `:root` tokens in `style.css`.
